# Nexora TMS — Identity, credential and session contract

- Status: Accepted for NEX-68
- Scope: API resource server + Web authentication boundary
- Production impact: none; Production remains frozen until the v0.2.0 Go/No-Go.

## Decision

The Nexora API remains a stateless OAuth 2.0/OIDC resource server while it authenticates requests with Bearer access tokens.

The API MUST NOT create or persist a local login session and MUST NOT persist access tokens, refresh tokens, ID tokens, authorization codes, PKCE verifiers, passwords, client secrets or raw OIDC subjects in audit storage.

A request is authenticated only after the API has validated the Bearer token signature, exact issuer, intended API audience and allowed algorithm, then resolved the verified `(provider, subject)` pair to an active Nexora user.

## Web/API boundary

NEX-70 MUST implement the browser login with Authorization Code + PKCE and a Web-owned secure session. Browser JavaScript MUST NOT persist OAuth tokens in `localStorage`, `sessionStorage` or other script-readable durable storage.

The Web session is responsible for obtaining or renewing credentials for calls to the API. API requests continue to use `Authorization: Bearer <access-token>` with the environment-specific audience.

The Web session cookie MUST be `HttpOnly`, `Secure` outside local development and use an explicit `SameSite` policy. Session material exposed to the browser MUST be opaque or cryptographically protected and MUST NOT contain reusable OAuth secrets in plaintext.

## Logout, expiry, revocation and recovery

- Logout terminates the Web session and delegates provider logout to Auth0 as defined by NEX-70.
- After logout, the Web MUST NOT reuse credentials from the terminated session.
- Access-token expiry is enforced by API JWT verification.
- Wrong issuer, audience, signature or algorithm is rejected before local identity resolution.
- Provider-side revocation or logout does not create a Nexora API session-revocation table; the API remains stateless.
- An already-issued self-contained access token remains bounded by provider capabilities and its expiry.
- The terminated Web session cannot reacquire or reuse credentials after logout.
- Password reset and account recovery are delegated to Auth0; Nexora never stores or handles the user's password.

## Stable API authentication outcomes

- Missing or malformed Authorization header: `401`; audit `auth.bearer.missing`.
- Invalid, expired, wrong-issuer or wrong-audience token: `401`; audit `auth.bearer.rejected`.
- Verified external identity not linked to an active Nexora user: `401`; audit `auth.identity.unlinked`.
- Verified external identity mapped to an active Nexora user: request continues; audit `auth.identity.accepted`.
- Authenticated user lacking a tenant permission: `403`; tenant-scoped authorization audit.
- Tenant source conflict or isolation violation: denied through the tenant-scoped security and audit path.

Authentication responses MUST NOT reveal whether a tenant exists and MUST NOT echo token claims or secrets.

## Pre-tenant authentication audit

Authentication can fail before a tenant exists. Those events are stored separately in `pretenant_auth_events`, introduced by migration `0025_pretenant_auth_audit.sql`, rather than forcing a fake `tenant_id` into the tenant-scoped `audit_events` model from Wave 0024.

The pre-tenant table is append-only. `nexora_app` receives INSERT only. It stores:

- UUIDv7 event id generated by the API;
- event type and outcome;
- provider key only after token verification;
- SHA-256 fingerprint of `(provider, subject)` rather than the raw subject;
- resolved user id when available;
- request and correlation ids when supplied.

It never stores JWTs, OAuth credentials, passwords, client secrets, raw subjects or arbitrary metadata or payloads.

## Gate for NEX-68

NEX-68 can be marked Done only when CI proves the guard and audit tests plus migration integrity, the implementation is merged into `main`, and Jira records the resulting SHA. NEX-70 may then implement the concrete Auth0 Web session against this contract.
